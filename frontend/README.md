# FCC 프론트엔드 프로토타입

사용자가 제공한 참고 이미지의 밝은 파란색, 왼쪽 메뉴, 상단 프로필, 카드 배치를 적용한 임시 화면입니다. React + Vite + TypeScript + CSS를 사용합니다. 위치와 흐름은 UX 검토 후 바꿀 수 있습니다.

## 실행

실행할 컴퓨터에 Git과 Node.js가 설치되어 있어야 합니다. Node.js 22.19.0 / npm 10.9.3에서 확인했습니다. Node.js를 설치하면 npm도 함께 설치됩니다.

### 저장소를 처음 받는 경우

코드를 보관할 폴더에서 터미널을 열고 순서대로 실행하세요. 프로토타입이 있는 `frontend` 브랜치를 받습니다.

```sh
git clone --branch frontend https://github.com/hy2oni/family-care-cloud.git
cd family-care-cloud/frontend
npm ci
npm run dev
```

### 이미 저장소가 있는 경우

수정 중인 작업을 먼저 커밋하거나 별도로 보관한 뒤, `family-care-cloud` 저장소 폴더에서 실행하세요.

```sh
git fetch origin
git switch frontend
git pull --ff-only origin frontend
cd frontend
npm ci
npm run dev
```

`git switch`가 로컬 변경 때문에 중단되거나 `git pull --ff-only`가 실패하면, 강제로 덮어쓰지 말고 팀에 현재 상태를 공유하세요.

### 이후 다시 실행하는 경우

이미 패키지를 설치했다면 `frontend` 폴더에서 다음 명령만 실행하면 됩니다. 새 코드를 받은 뒤에는 `npm ci`를 다시 실행해 패키지 버전을 맞춰 주세요.

```sh
npm run dev
```

터미널에 표시된 로컬 주소(보통 `http://localhost:5173/`)를 브라우저에서 엽니다. 포트가 사용 중이면 주소가 달라질 수 있으니 터미널의 안내를 따르세요. 개발 서버가 켜져 있을 때만 접속할 수 있으며, 종료하려면 해당 터미널에서 `Ctrl+C`를 누릅니다.

각자 자신의 컴퓨터에서 실행하므로 최초 개발자의 노트북이 켜져 있을 필요는 없습니다. 가상 기록은 각자의 브라우저에 따로 저장되며 다른 사용자와 공유되지 않습니다. 기본 로컬 시연에는 백엔드 서버나 `.env` 파일이 필요하지 않습니다.

## 구현 범위

| 메뉴        | 확인할 수 있는 동작                                                                             |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 대시보드    | 오늘 기록 수, 현재·다음 보호자, 최근 기록, 앞으로 예정된 일정, 인수인계 예시                    |
| 돌봄 기록   | 작성·목록·상세·수정·삭제, 날짜·유형 필터, 작성자 및 발생·작성 시각                              |
| 일정        | 등록·수정·삭제, 담당자 지정, 오늘·상태별 조회, 예정·완료·취소 변경                              |
| AI 인수인계 | 기간 선택, 가상 결과 생성·재생성, 이력 조회, 다음 보호자 확인                                   |
| 가족 관리   | 그룹 생성·참여·탈퇴, 초대 코드 화면, 구성원, 고령자 등록·수정·연결, 다음 보호자 지정, 교대·이력 |
| 상단 프로필 | 가상 프로필 수정, 로그인·회원가입·로그아웃 화면 흐름                                            |

돌봄 기록만 이 브라우저의 localStorage(`fcc.demo.care-events.v1`)에 저장됩니다. 실제 DB 저장이나 계정 간 공유가 아닙니다. 일정·가족·프로필·교대·인수인계 시연 상태는 메뉴를 이동해도 유지되지만 새로고침하면 초기화됩니다. 서로 다른 그룹의 데이터 분리와 실제 접근권한은 구현하지 않았으며 그룹 변경 시 기존 가상 기록을 유지합니다.

AI 결과는 선택 기간의 기록 원문을 유형별로 묶은 것이며, 실제 요약·분류 모델을 호출하지 않습니다. 예정 일정은 생성 시점 이후 일정으로 구성합니다. 인수인계 자동 생성 여부는 합의 전이므로 현재는 수동 생성 버튼을 사용합니다. 로그인·초대는 실제 요청을 보내지 않습니다. 시연 초대 코드는 `FCC-DEMO`입니다.

음성 도우미·승인 요청·이동 모니터링은 초기 범위에서 제외했습니다. 메뉴는 단일 화면의 상태 전환이며 아직 URL별 라우팅을 사용하지 않습니다.

## 검증

```sh
npm run lint
node --experimental-strip-types --test data.test.mjs
npm run build
```

기록 메뉴 하단의 **시연 도구**로 저장 실패·조회 실패·빈 목록·예시 복원을 확인할 수 있습니다. 초기화는 직접 작성한 가상 기록도 지우므로 확인창을 거칩니다.

일반 프로덕션 빌드는 가상 화면을 자동 활성화하지 않고 연결 준비 안내를 표시합니다. 로컬에서 프로덕션 시연 빌드를 확인하려면 `.env.example`을 참고해 `.env.local`에 `VITE_ENABLE_DEMO=true`를 명시한 뒤 빌드하세요. 실제 서비스 빌드에는 이 설정을 사용하지 않습니다. Vite 환경변수는 빌드 시 반영됩니다.

`node_modules/`, `dist/`, 실제 환경 파일은 Git에서 제외하고 `package-lock.json`은 관리합니다. 외부 웹폰트를 불러오지 못하면 시스템 한글 글꼴을 사용합니다.

## 백엔드 연결 위치

- `src/data.ts`: 가상 DTO, 샘플 데이터, `createMockCareApi` 및 `getCareApi` 경계. 기록 목록·저장·삭제를 실제 API로 교체할 첫 위치입니다.
- `src/Records.tsx`: 화면·입력 검증·로딩·오류 및 재시도 처리. API 교체 후 실제 응답에 맞게 조정합니다.
- 나머지 시연 메뉴: 현재 React 상태만 변경합니다. API 합의 후 데이터 접근 계층으로 옮겨 연결합니다.
- `.env.example`: 공개 API 주소 설정 예시. `VITE_API_BASE_URL`은 아직 호출에 사용하지 않습니다. AWS 인증정보나 AI 키를 넣지 않습니다.

다음 사항을 백엔드와 합의해야 합니다.

1. 기록 API 경로·HTTP 방식, 필수값, 유형 코드, 성공·오류 응답 형식.
2. 발생 시각(`timestamp`)과 작성 시각(`createdAt`)의 날짜 형식·시간대.
3. 작성자 이름 제공 방식, 정렬 기준·페이지 처리·기간 필터.
4. 인증 전달 방식, 사용자·그룹·고령자 ID, 그룹별 접근권한.
5. AI 즉시 응답 또는 작업 ID 조회 방식, 교대 시 자동 생성 여부, 확인 상태 저장 방식.
6. 개발용 서버 주소, CORS 및 배포 방식.

실제 연결 완료는 서버에 저장한 기록이 새로고침 후 DB에서 조회되고, 로그인·그룹 권한이 적용되는 단계입니다. 현재는 해당 단계가 아닙니다.
